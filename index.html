    Entregue

    Simulação roteirizada, roda só no seu navegador. O bot de verdade conversa pela API do Claude e segue o roteiro que cada empresa configura.

    O que acontece entre a mensagem e o recado

    1. Chega pelo webhook

      Cada empresa tem a própria URL, com um segredo que é conferido em tempo constante. Segredo errado, requisição recusada.

      /webhook/:cliente/:segredo

    2. Espera você terminar

      Mensagens mandadas em sequência são juntadas por 4 segundos antes de ir para o modelo, como uma pessoa que espera o cliente terminar de falar.

      messageBuffer · 4 s

    3. O modelo responde

      O Claude recebe a base de conhecimento, as unidades, os horários e o roteiro da empresa. A parte fixa do prompt fica em cache para custar menos.

      botService → Claude API

    4. As marcas viram ação

      O modelo sinaliza o estado com marcas curtas. Elas são tiradas antes de qualquer coisa chegar ao cliente.

      [FILIAL:N] [LEAD_PRONTO] [HUMANO] [NOME:x]

    Perfeito, Ana! A unidade Savassi fica na Rua Pernambuco e abre sábado de manhã. Já passei seu pedido para a equipe de lá, eles te chamam por aqui ainda hoje. [NOME:Ana] [FILIAL:2] [LEAD_PRONTO]

    • [NOME:Ana] salva o nome do cliente na conversa
    • [FILIAL:2] escolhe a unidade Savassi
    • [LEAD_PRONTO] manda o resumo para a unidade, com botão para assumir a conversa

    Um servidor, muitas empresas

    Cada empresa com o seu balcão

    Base de conhecimento, unidades, horários e perguntas de triagem próprias. Uma instalação atende vários clientes sem misturar nada.

    Roteiro que você escreve

    A lista de perguntas que o cliente precisa responder antes de virar recado é definida por empresa.

    Fechado é fechado

    Fora do horário a resposta é um texto fixo, sem chamar o modelo.

    Uma pessoa a qualquer momento

    O cliente pode pedir atendente. A unidade é avisada e o bot continua respondendo enquanto ninguém assume.

    Recado não fica esquecido

    Se a unidade não responde em 30 minutos, ela recebe um lembrete.

    Custo sob controle

    Cache de prompt, contexto curto e uso de tokens contado por empresa. No limite do plano o bot continua atendendo e o excedente é registrado.

    Relatório toda semana e painel de administração

    Resumo semanal para cada empresa e para quem opera. No painel: cadastro de clientes, recados recebidos e estatísticas de uso.

    Feito para não vazar

    Um bot que recebe mensagem de cliente pela internet é uma porta aberta. Estas são as trancas.

    • Nenhum segredo no repositório. Tudo vem de variáveis de ambiente, e o servidor se recusa a subir sem MONGODB_URI, CLAUDE_API_KEY e ADMIN_PASSWORD.
    • Segredo por empresa no webhook, comparado com crypto.timingSafeEqual para não vazar informação pelo tempo de resposta.
    • Cabeçalhos de segurança com helmet e limite de requisições com express-rate-limit no webhook e no painel.
    • Painel na mesma origem, com política de segurança de conteúdo e senha por bearer na API de administração.
    • Teste que não dispara sem querer. As ferramentas de teste se recusam a mandar mensagem de verdade para uma empresa com gateway ativo sem uma confirmação digitada.
    • Transporte isolado. Todo o código do gateway fica em dois arquivos, então dá para trocar pela API oficial do WhatsApp Business sem mexer na conversa.

    Rode na sua máquina

    Node.js 18+, Express, MongoDB, API do Claude, Jest. O test-local conversa com o bot no terminal sem mandar nada pelo WhatsApp.
